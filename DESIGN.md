# Tahoe Code: design notes

How Tahoe Code works, what it doesn't do, and what I changed along the way. The code is in `src/`; file names below are relative to it.

## Staying inside code blocks

The editor features are CodeMirror 6 extensions registered with `registerEditorExtension`, so they run in Obsidian's own editor, plus a few wrapped Obsidian commands. Each one first checks for a code block (`blockAt`/`blocksOf` in `blocks.js`) and does nothing outside one; that check is what keeps the rest of the note untouched. The one exception is equation to code, which acts on a `$…$` or `$$…$$` equation in prose.

- **Finding blocks.** `blocks.js` scans the document line by line with one regex for an opening fence (```` ``` ```` or `~~~`, three or more, optionally inside callout `>` markers or a list indent) and looks for the matching closing fence. The result is cached per document object in a `WeakMap`, so a scan happens once per edit, not once per feature.
- **Language.** The word after the fence is looked up in an alias table (`langs.js`: `py`, `python3`, `ipython` are all Python, and so on). A block whose language isn't in the table is ignored, as if it were prose.
- **Callouts and lists.** A block inside `> ` keeps its prefix on every line. `blockCode` strips the prefixes and returns the bare code plus `toDoc`/`fromDoc` functions that map offsets back to the document, so everything else works on clean code.
- **Indent unit.** `indentUnitOf` reads the block's own lines: tabs if most indented lines use tabs, otherwise the GCD of the space widths if it's 2, 3 or 4. Any other GCD (a lone line indented 8, say) falls back to the language's default from `langs.js`, as does a block with no indented lines yet (4 for Python, 2 for JavaScript, a tab for Go).
- **Obsidian's own hotkeys.** ⌘/, ⌘D, ⌘B, ⌘I, ⌥↩ and ⌘↩ are Obsidian commands, and they run before editor keymaps. `patchCommand` in `main.js` wraps each command's callback: inside a code block it runs the code version (comment in the block's language, duplicate line, go to definition, and so on); if that doesn't apply, or outside a block, it calls the original. ⌘I also acts on an equation in prose. ⌘I, ⌥↩ and ⌘↩ are wrapped on desktop only. The wrappers are undone on unload. Since 1.3.1 it also wraps plain check callbacks, because from Obsidian 1.14 that's how follow link (⌥↩) and open link in a new tab (⌘↩) are defined.

## Without a language server

The features that work everywhere, phones included, have no parser behind them. `lexer.js` is a small hand-written tokeniser driven by each language's entry in `langs.js` (comment markers, quote characters, Python's triple quotes, MATLAB's transpose `'`, doubled quotes in MATLAB and SQL). It produces strings, comments, brackets, identifiers, numbers and punctuation, then pairs the brackets with a stack. Its own header says "It's not a parser". The last 24 results are memoised, because every keystroke asks for them. Smart Enter, indentation and `end` insertion are per-language regexes in `langs.js` (`indentAfter`, `dedents`, `ends`).

- **Bracket colours** come from the lexer's nesting depth (three colours, cycling), applied only to lines on screen. With the cursor next to a bracket, it and its partner are marked; if it has no partner it's shown in red.
- **Suggestions** (`complete.js`) are built from three sources: identifiers already used in the note's blocks of the same language, a keyword and built-in list per language (some, like CSS, JSON and YAML, have none), and templates and postfix completions. Results from other plugins (Tahoe Run's running session, and on desktop the language servers) are merged in only if they come back within 350 ms. Matching uses CodeMirror's autocomplete with one extra rule: the first letter has to match. Names you pick get a ranking boost that is saved with the settings. No list opens where you're naming something new (`as`, `def`, `class`, a `for` target, parameters, `const`/`let`, a C type); that check is a regex per language family.
- **Uses of a name and rename (⇧F6)** are both plain token matches: every identifier token with the same text, skipping strings and comments. Uses are highlighted across the note's blocks of that language. Rename puts a cursor on each match inside the current block only. Neither knows about scope, so a local `x` and a global `x` count as the same name, and so does `obj.x`.
- **Go to definition** (`navigate.js`) asks the language server first if one is running for that language. Otherwise it tries a list of regexes per language family (`def name`, `class name`, `import … as name`, assignments, `for name in`, C declarations, and so on), most specific first, over the note's blocks in order, skipping matches inside strings and comments. The first match wins. If you're already on the definition, it goes to the next use instead. If no pattern matches, it says it couldn't find it.
- **Sticky headers** (`sticky.js`) use indentation. Starting from the first line on screen, the scan walks upward collecting each less-indented line that opens a scope: a per-language regex (`def`/`class`/`for … :` in Python, `function`/`if`/`for` in MATLAB-like languages, a line ending in `{` in C-like languages; the shell and YAML have their own rules). It keeps up to three. The rows are copies of the real line elements, so they keep their colours. A tab counts as 4 columns here.
- **Misspelt-name cards** are not from the tokeniser. They come from the desktop checker below, and their quick fixes are attached to the diagnostic.

Limits that follow from this: no types, no scopes, no cross-file knowledge, and names are matched as text. A pattern-based definition can find the wrong line when a name is assigned in several places (the first match in pattern order wins). Indent guides are skipped in blocks inside callouts and lists.

## Desktop only

Checking, quick fixes, language servers, real formatters, ghost text and ⌘I live in `desktop/` and are started only when `Platform.isDesktop` is true. They need Node to start programs and write temporary files, and Obsidian on phones and tablets has no Node. `node.js` loads `fs`, `path`, `os`, `child_process` and `http` with `import()` on desktop only. On a phone those stay `null` and nothing that needs them runs. Everything outside `desktop/` works on both.

- **Finding tools.** `desktop/tools.js` builds a `PATH` from the login shell (`$SHELL -l -c 'printf "%s" "$PATH"'`) plus the usual Homebrew and user bin folders, so tools installed outside Obsidian's environment are found. It also looks in Xcode's toolchain and in the MATLAB app for `mlint`. Scratch files go in one `mkdtemp` folder in the system temp directory.
- **Checking** (`desktop/lint.js`) runs about 900 ms after you stop typing. Each block goes to the language's own tool: `clang`/`clang++ -fsyntax-only`, `swiftc -typecheck`, `node --check`, `javac`, `ruby -wc`, `perl -c`, `bash -n`, MATLAB's `mlint`. Results are cached by block text, so unchanged blocks aren't checked again. MATLAB message IDs that are noise in a notebook (the "add a semicolon" family, "might be unused") are dropped. A language with a running language server uses the server's diagnostics instead.
- **Misspelt names in Python** come from a short Python script run with `python3`. It parses the block with `ast`, collects every name bound in the note's earlier Python blocks and in this one, and reports each loaded name that isn't bound. Close matches come from `difflib.get_close_matches` (cutoff 0.8). The quick fixes are "Change to …" for each match and "Add …" (for example "Add import numpy as np" or "Add from pathlib import Path") from a table of common aliases (`np`, `pd`, `plt`, …) and the standard library. For Pyright's "is not defined" errors, the same fixes are offered, with candidates ranked by Damerau–Levenshtein distance instead.
- **Other quick fixes.** C, C++ and Objective-C use clang's `-fdiagnostics-parseable-fixits` output and clangd's code actions. Java gets "Insert ';'" when `javac` reports `';' expected`.
- **Language servers** (`desktop/lsp.js`) speak JSON-RPC over stdio. Each block is written as its own file (`block<N>.<ext>`) in a per-note folder. For Python and MATLAB, the note's earlier blocks of that language are prepended, so names defined above are known; positions are shifted by those prefix lines, and a definition that lands in an earlier block is ignored. Pyright gets a notebook profile: undefined names stay errors, type issues become warnings, and redeclaration and possibly-unbound are off. A server that exits is restarted, and after three failures it is marked as failed.
- **Format (⇧⌥F)** runs clang-format, swift-format, ruff or black, gofmt, rustfmt, shfmt or stylua when installed, passing the block's indent width to the tools that take one (clang-format, swift-format, shfmt). Otherwise, and on phones, `format.js` tidies: it trims trailing spaces and re-indents languages whose indentation is only for show. Python, YAML and Haskell keep their depth, because there it's meaning.
- **⌘I and ghost text** talk to Ollama on `127.0.0.1:11434`, or to Apple Intelligence through the Tahoe Intelligence plugin if it is present. "Automatic" picks a different model for each. Ghost text takes the smallest coding model, using fill-in-the-middle; the code says big models are too slow to keep up with typing. ⌘I prefers a model with "coder" in its name between 3 and 12 GB, then a general model between 2 and 10 GB, then any other coder model, then Apple Intelligence. ⌘I shows the result as a line diff (an LCS table in `desktop/inline.js`); ⌘↩ keeps it and Esc discards it. Typing inside the lines being rewritten cancels it.

Ghost text uses Obsidian's `requestUrl`, but ⌘I uses Node's `http` directly, so the request can be cancelled: `requestUrl` can't be stopped once it's sent, and an edit can take a while.

## What changed along the way

My development history (in a private repository) starts with a snapshot of the whole project on 12 October 2026, so anything tried before that isn't recorded; this repository's own history starts at 1.3.0 on 15 October 2026. Changes since 12 October:

- **Glass popups, removed minutes later.** I gave suggestion lists, docs and hover cards the theme's refracting glass, with the list and its docs as two separate glass panels. In the next commit the Tahoe theme switched them to near-solid cards with no refraction (that styling is in the theme, not this plugin), so the code behind never shows through the text. The docs panel beside suggestions went from shown to off by default in the same commit (it can be set to show after a pause, or always).
- **Popups stay in the pane.** Suggestion lists and hover cards are kept 12 px inside the note's pane (CodeMirror's `tooltipSpace`) and flip sides rather than being cut off.
- **Hover cards.** Language-server docs wait 700 ms before showing (problem cards use CodeMirror's default). Hover cards close on a click anywhere in the editor outside the card, and let clicks pass through to the code. The exception is a card with buttons (a problem's quick fixes), which keeps the pointer.
- **Quieter suggestions (two rounds).** First: no docs for keywords, no list for a suggestion that is exactly what you typed (it would only swallow Enter), and shorter docs. Second: the first letter has to match (before, `np` offered `input`); no list where you're naming something new (`import numpy as np` used to become something else on Enter); and Enter accepts a suggestion only if it starts with what you typed or you chose it with the arrow keys. Otherwise Enter makes a new line, and Tab always accepts. Between the two rounds, a fix stopped language-server keyword items from appearing for a fully typed word.
- **Ghost text that chatted.** With nothing after the cursor, Ollama's fill-in-the-middle answered like a chat ("It looks like you're working with…"). Sending a newline as the suffix fixed it. As a second guard, output that looks like prose is dropped, and a suggestion is cut to the rest of the line, or a block's body up to a blank line.
- **Hover docs and parameter hints cut down.** Parameter hints show the signature, plus the current parameter's one-line note if it has one. Hover docs show the signature and the first paragraph, because numpy's full docstrings run to pages.
- **For the community directory (1.3.0)** I moved the sources from CommonJS to ES modules, with Node's modules behind `node.js`. I removed `:has()` and `!important` from the styles: cards that need the pointer are now marked with a class by a `MutationObserver`. I dropped ⇧⌥F as a default command hotkey; it's now an editor key that only acts inside a code block. minAppVersion went to 1.13.0.
- **1.3.2.** Pyright knows `display()`, as notebooks (and Tahoe Run's kernel) have it: a `__builtins__.pyi` in its workspace declares it. Problem underlines and the unmatched-bracket mark are drawn as small images, as CodeMirror does, because the review flagged `text-decoration` styling as only partly supported; the equation preview selects MathJax output by its class rather than its element name.
- **Speed.** Bracket colours, guides and uses highlighting are recomputed on a cursor move only when the cursor is in a code block before or after it, not on every click in prose.

## Testing

The tests live in my private development repository, not in this one. This repository has the sources, the build and a release workflow.

- **Unit tests** (plain Node, with stand-ins for Obsidian and CodeMirror) load this plugin's source files directly. They cover the lexer (MATLAB strings, transpose and comments; bracket pairing), finding code blocks, templates and postfix, sticky-header scopes, near-name and import quick fixes, the ⌘I diff, finding the equation at the cursor, no suggestions while naming, and ghost-text cleanup.
- **Scenarios in a real Obsidian.** A script drives a hidden copy of Obsidian with its own settings and a fresh vault (never my own vault). It checks that the plugins load, suggestions appear (and not for a word already typed), clicks go through hover cards, ⌥↩ quick fixes work, and equation to code works in Python and MATLAB against a local model.
- **Before a release** I also run `eslint-plugin-obsidianmd` (the lint Obsidian's review uses) in a checkout of this repository; its config isn't committed here.
- **Not tested:** the desktop tools assume macOS (PATH handling, the login shell, Xcode, /Applications) and haven't been tried on Windows or Linux.
